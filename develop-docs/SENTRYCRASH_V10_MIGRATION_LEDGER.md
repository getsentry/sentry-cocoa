# SentryCrash V10 Migration Ledger

## Contract

- Baseline: `060c1728d`, before V10 recorder source exclusion.
- Implementation boundary: `Sources/SentryCrash/**`.
- SDK-owned files remain SDK-owned regardless of `SentryCrash` or `sentrycrash` spelling.
- `working`: V10 has a positive route and test.
- `temporary`: V10 behavior is reduced; keep `SENTRY_DISABLE_SENTRYCRASH_V10` until the acceptance test passes.
- `decision`: product or compatibility semantics must be confirmed before changing the route.
- V10 compile-out tracker: [#8528](https://github.com/getsentry/sentry-cocoa/issues/8528).
- Repository-wide removal after V9 retirement: [#8319](https://github.com/getsentry/sentry-cocoa/issues/8319).
- Downstream SPI audit: [#8738](https://github.com/getsentry/sentry-cocoa/issues/8738).

## Headers and Compatibility

- Public compatibility retained:
  - `SentryCrashExceptionApplication` — implementation currently has the SCV10-012 forwarding gap.
  - `__sentry_cxa_throw`, `__sentry_cxa_rethrow` — SCV10-029.
- SDK-owned historically named types retained:
  - `SentryCrashReportConverter`.
  - `SentryCrashDefaultMachineContextWrapper` and stack boundary models while SCV10-003 remains.
  - `SentryScopeSyncC.c`, `SentryCrashScope`, and all `sentrycrash_scopesync_*` APIs.
- V10 packaging contract:
  - `SentryCrashReportSink.h` and `SentryCrashScopeObserver.h` are not packaged because their V9-only implementations are absent.
  - Generated V10 headers do not declare the excluded Swift adapter classes.
  - `SentryCrashExceptionApplication.h` remains public compatibility, and `SentryCrashReportConverter.h` remains an SDK-owned private header.
  - `SentryPrivate.h` still imports recorder installation, monitor, report-filter, and callback headers for source builds.
  - V10 header search paths still expose `Sources/SentryCrash/**` until Stack 16/17 removes stale source-level header dependencies.
- Keep Tool headers required by the retained SDK-owned consumers until each Tool implementation is replaced.
- `scripts/verify-v10-sentrycrash-framework.sh` enforces packaged-header provenance for dynamic and static frameworks.

## Contract Enforcement

- `scripts/verify-v10-sentrycrash-source-contract.sh` inspects source annotations, ledger references, and reviewed SDK-owned exclusions.
- `scripts/verify-v10-sentrycrash-objects.sh` inspects compiled objects against the retained Tool and guarded-translation-unit contract.
- `scripts/verify-v10-sentrycrash-framework.sh` inspects final framework symbols, classes, compatibility APIs, and packaged headers.
- Detailed purpose, guarantees, and limitations are documented at the top of each script.

## Decisions

- **SCV10-007 and SCV10-033 — managed runtimes:** Preserve early signal-handler ordering and per-thread one-shot `ignoreNextSignal` semantics in V10 so downstream SDKs, especially .NET, can convert native hard faults to managed exceptions without duplicate reports. Keep `ignoreNextSignal` restricted SPI. Track both capabilities in [#8797](https://github.com/getsentry/sentry-cocoa/issues/8797); #8738 does not cover this implementation work. Remove the contract only if supported downstream .NET versions are proven unaffected.
- **SCV10-037 — legacy SPI types:** Do not retain V10 source or ABI facades for `SentryCrashSwift`, `SentryCrashBridge`, `SentryDefaultCrashReporter`, or report-filter types. Their SPI visibility supports SDK-internal Swift/ObjC bridging and does not establish a downstream compatibility contract. Use #8738 to verify and coordinate downstream migration.
- **SCV10-001 — binary images:** Use [#8798](https://github.com/getsentry/sentry-cocoa/issues/8798).
- **SCV10-003 — thread inspection:** Use [#8799](https://github.com/getsentry/sentry-cocoa/issues/8799).
- **SCV10-016 and SCV10-017 — memory and context:** Use [#8800](https://github.com/getsentry/sentry-cocoa/issues/8800).
- **SCV10-026 — low-power scope updates:** Use #8736. Duplicate #8737 is closed.
- **SCV10-039 — replay recovery:** Use [#8801](https://github.com/getsentry/sentry-cocoa/issues/8801), linked to #8758's KSCrash callback infrastructure. Keep replay-specific acceptance tests independent from report enrichment.
- **Tracker hierarchy:** #8528 tracks removal of V10's SentryCrash dependency and remains open until V10 no longer needs it. #8319 tracks repository-wide removal only after V9 is retired.
