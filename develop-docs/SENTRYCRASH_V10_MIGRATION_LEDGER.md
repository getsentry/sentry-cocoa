# SentryCrash V10 Migration Ledger

## Contract

- Baseline: `060c1728d`, before V10 recorder source exclusion.
- Implementation boundary: `Sources/SentryCrash/**`.
- SDK-owned files remain SDK-owned regardless of `SentryCrash` or `sentrycrash` spelling.
- `working`: V10 has a positive route and test.
- `temporary`: V10 behavior is reduced; keep `SENTRY_DISABLE_SENTRYCRASH_V10` until the acceptance test passes.
- `decision`: product or compatibility semantics must be confirmed before changing the route.
- Every `KSCRASH_TODO` must reference at least one GitHub issue, for example `KSCRASH_TODO(GH-1234): description`; `scripts/verify-v10-sentrycrash-source-contract.sh` enforces this.
- V10 compile-out tracker: [#8528](https://github.com/getsentry/sentry-cocoa/issues/8528).
- Repository-wide removal after V9 retirement: [#8319](https://github.com/getsentry/sentry-cocoa/issues/8319).
- Downstream SPI audit: [#8738](https://github.com/getsentry/sentry-cocoa/issues/8738).

## Contract Enforcement

## Decisions

- **SCV10-007 and SCV10-033 — managed runtimes:** V10 preserves early signal-handler ordering and per-thread one-shot `ignoreNextSignal` semantics through a Sentry-owned Signal plugin registered with KSCrash, so downstream SDKs, especially .NET, can convert native hard faults to managed exceptions without duplicate reports. The only KSCrash upstream addition is generic Mach exception-mask configuration. `ignoreNextSignal` remains restricted SPI. The implementation is tracked by [#8797](https://github.com/getsentry/sentry-cocoa/issues/8797); #8738 does not cover this contract.
- **SCV10-037 — legacy SPI types:** Do not retain V10 source or ABI facades for `SentryCrashSwift`, `SentryCrashBridge`, `SentryDefaultCrashReporter`, or report-filter types. Their SPI visibility supports SDK-internal Swift/ObjC bridging and does not establish a downstream compatibility contract. Use #8738 to verify and coordinate downstream migration.
- **SCV10-001 — binary images:** The backend-neutral `SentryBinaryImageCache` owns lifecycle and retention. V9 uses a callback adapter; V10 pulls KSCrash RecordingCore images, includes dyld explicitly, and leaves KSCrash's single image-added callback slot untouched. UUID conversion uses Foundation. See [#8798](https://github.com/getsentry/sentry-cocoa/issues/8798).
- **SCV10-003 — thread inspection:** Use [#8799](https://github.com/getsentry/sentry-cocoa/issues/8799).
- **SCV10-016 and SCV10-017 — memory and context:** Completed under [#8800](https://github.com/getsentry/sentry-cocoa/issues/8800). `SentryExtraContextProvider` reads an SDK-owned memory provider directly, while `SentryHub` uses an SDK-owned scope enricher and system-info provider in both V9 and V10. The broad reporter no longer exposes memory, system-info, or scope-enrichment capabilities.
- **SCV10-038 and SCV10-040 — placeholder reporter removal:** Completed under [#8800](https://github.com/getsentry/sentry-cocoa/issues/8800). Shared Hub and watchdog paths consume `SentryCrashReporterState` and an injected SDK-owned simulator value; V10 obtains active state from `SentryKSCrash.Query`. `SentryCrashReporter`, its dependency-container factory, and `SentryDefaultCrashReporter` remain V9-only. V10 has no broad or unavailable reporter facade.
- **SCV10-015 — initial crash user info:** Composition of release/dist/environment is working via `SentryKSCrash.Scope.Configuration`. Nested containers remain a KSCrash KV limitation in [#8756](https://github.com/getsentry/sentry-cocoa/issues/8756); crash reports get those fields from the SCV10-013 observer seed instead.
- **SCV10-026 — low-power scope updates:** Completed in `SentryKSCrash.Scope.Configuration`. #8737 closed via #8760; #8736 remains a stale open duplicate.
- **SCV10-039 — replay recovery:** Completed under [#8801](https://github.com/getsentry/sentry-cocoa/issues/8801), linked to #8758's KSCrash callback infrastructure. KSCrash `didWriteReport` writes the checkpoint before attachment capture. Keep replay-specific acceptance tests independent from report enrichment.
- **Tracker hierarchy:** #8528 tracks removal of V10's SentryCrash dependency and remains open until V10 no longer needs it. #8319 tracks repository-wide removal only after V9 is retired.
