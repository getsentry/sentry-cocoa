Hints API for sentry-cocoa

Cross-SDK analysis of hint implementations and recommendations for Apple

What is a Hint?

A Hint is SDK-specific metadata about the origin of an event or breadcrumb — the raw, original data that triggered the capture. It flows alongside the event through beforeSend, beforeBreadcrumb, and event processors, giving callbacks access to source material the processed event no longer carries.

SDK Implementations Compared

sentry-java Rich

Type: Thread-safe class with typed fields

Storage: Generic key-value + typed attachment accessors

Keys: 46 constants via TypeCheckHint

Extras: Marker interfaces for pipeline control, clear() preserves SDK-internal keys

sentry-python Minimal

Type: Plain Dict[str, Any]

Storage: Untyped key-value dictionary

Keys: 3 documented: exc_info, log_record, httplib_request

Extras: Scope adds attachments key; defensively handles None

sentry-unreal Consumer

Type: USentryHint UObject wrapping native hints

API: Only AddAttachment()

Android: Wraps Java Hint via JNI

Apple: Always passes nullptr

sentry-cocoa None

Type: No hint concept exists

Callbacks: beforeSend, event processors take only the event

Gap: Original NSException/NSError discarded before callbacks run

Impact: Unreal gets nullptr, hybrid SDKs have no access

Pipeline Flow (Java reference)

The same Hint object flows through every stage — this is the model to follow:

Hint created or new Hint() → Scope attachments added → applyScope → Event processors → beforeSend → hint.clear() → Transport

Design Decisions

  • 01 Class vs. dictionary. Java uses a class with typed accessors; Python uses a plain dict. A class (SentryHint) is the right fit for Cocoa — it gives ObjC compatibility, typed properties for common fields, and generic storage via set/object(forKey:). Matches Java's proven approach.
  • 02 Thread safety. Java's Hint is fully synchronized. Since Cocoa callbacks may fire from different queues, SentryHint should use a lock or serial queue for its internal storage — same pattern as SentryScope.
  • 03 Marker interfaces → not needed. Java uses marker interfaces (Cached, Backfillable, SessionStart) on hint objects for internal pipeline control. This is a Java-specific pattern. In Cocoa, internal flags can live as private properties or SDK-internal keys (prefixed sentry:), keeping the public API clean.
  • 04 Backward compatibility. Adding a SentryHint parameter to beforeSend is a breaking change. Options: (a) add new callback properties like beforeSendWithHint that take precedence, (b) use overloaded closures (Swift only), or (c) accept the break for the next major version. Java took approach (a) historically before consolidating.
  • 05 Unreal parity. The minimum viable hint for Unreal is addAttachment() — this unblocks AppleSentryHint and stops passing nullptr. The typed attachment properties (screenshot, viewHierarchy) are the clear next step.
  • 06 Capture methods. captureException, captureError, captureMessage, and captureEvent should accept an optional SentryHint parameter, defaulting to a new empty hint. Internal callers populate it before invoking the pipeline.
  • 07 clear() before transport. Following Java, call clear() on the hint after beforeSend to prevent object leaks — but preserve SDK-internal keys. This is especially important since the hint may hold references to UIViews or view controllers.
